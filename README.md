# 序时 · 作品时间轴

一个简单易用的故事时间轴设定工具。由 **Symplatt** 设计并主导开发，Codex 辅助实现。

**当前版本：1.3.0** · Copyright © 2026 Symplatt. 版权所有。

## 安装与更新

从 [GitHub Release](https://github.com/Symplatt/story-timeline/releases/latest) 下载 `Xushi-Setup-1.3.0.exe`，运行后从桌面或开始菜单打开“序时”。安装包同时交付到本机 `D:\` 根目录。

面向 Windows 10/11 x64，采用当前用户安装，无需自行安装 Node.js。安装程序写入 Windows“已安装的应用”及卸载注册表项。请关闭旧版后安装新版；固定应用标识 `com.symplatt.xushi` 和安装目录用于覆盖更新。

作品数据独立保存在 `%APPDATA%\Xushi\workspace`。更新及卸载保留该目录；安装包和公开仓库不包含用户作品。1.3.0 兼容旧版单个国家字段、点分隔日期和 JSON 备份。旧版组织的非空层级名称转换为独立标签，原名称保留。更新前建议导出完整 JSON 备份。

## 使用

- **时间轴**：点击左上时间轴名称切换、新建或删除，旁边铅笔修改名称和简介。最多保存 1000 条时间轴，每条最多 10000 个节点。
- **添加与编辑**：右下角加号打开节点弹窗，只有事件必填。悬停或键盘聚焦节点时，旁边出现编辑、删除按钮。点击删除节点立即生效；删除整条时间轴仍需确认。
- **阅读**：中央时间轴只上下滚动。卡片按内容高度排布，默认显示前 100 个 Unicode 字符，超出显示省略号；“显示全文”直接展开原卡片，“收起全文”恢复预览。点击卡片选中，点击空白取消选择。下栏相邻显示总数／上限和筛选后数量。
- **事件格式**：支持加粗、下划线、斜体、删除线及屏蔽。屏蔽文字显示为黑色矩形，悬停或键盘聚焦揭示。屏蔽是阅读效果，JSON 仍包含原文。
- **时间**：可选择时间点或时间段，时间段分别填写开始时间和结束时间。每端都有时代、朝代、历法、日期、时刻五个文本字段，均可留空，不限制真实日历范围，允许 `1382.3.5` 和 `17:00:73` 等设定。留空的端点显示时间不确定。
- **地点**：编号 1—5 的五个层级，卡片以上标显示层级编号。
- **国家、组织和角色**：输入多个标签时用空格、换行或 Tab 分隔，自动去重并进入已有清单。拉丁字母自然排序，中文按拼音排序，中文和拉丁文字按中文排序器分组。清单可折叠，删除节点仍保留已录入标签以便复用。

## 筛选

左侧筛选区按字段分组，“取消所有筛选”一键恢复全部。每条时间轴分别保存筛选条件。

- **时间范围**：开始、结束各有五层时间，均选填。边界包含在结果中；时间段事件与筛选区间部分相交也符合。只填开始时显示此后所有事件，只填结束时显示此前所有事件。较粗边界覆盖完整已知层级，例如结束为 1999 年时包含当年所有月份。启用时间筛选后，完全未知时间的事件不计入；开始晚于结束会提示并显示零结果。
- **地点**：点击打开覆盖内容区的二级左栏，先选展示 1 至几级，再按各列选项筛选。各列独立滚动、可全选或全不选。同列为“任意选项符合”，不同列同时生效。仅填第三级的条目在第一、二级分别显示“未填写（3级 具体地点）”，可独立选中或排除。缩小展示层级会清除隐藏列条件。完全无地点的事件由单独开关控制。旧版本已有地点筛选保留原匹配规则，修改后切换为新方式。
- **国家、组织、角色**：均使用可折叠多选清单，同类别匹配任意一项。自定义“全部”复选按钮勾选表示全选（含无标签事件），取消表示全不选；部分选中显示半选状态，摘要用逗号连接。国家排在组织前面，组织不再具有层级。

不同类别与搜索条件同时生效。搜索包含事件、起止时间、地点、国家、组织和角色。输入框不显示 placeholder；节点表单的字段标题保留名称，字段组之间留出更大间距。

## 排序和显示设置

五层时间从时代向下逐层比较。时代、朝代、历法不进行数值或字母自动排序，由用户在“显示设置 → 当前时间轴的时间顺序”中分别长按条目后上下拖动编排（也可聚焦条目后按 Alt + 上下方向键），每条时间轴独立保存。新名称按录入先后加入列表末尾；旧数据首次打开时按节点记录中的出现顺序建立清单，之后可手动调整。日期、时刻继续按数字、字母自然排序。

共同时间部分相同时，模糊时间在前，精确时间在后。例如 `1999年` → `1999年5月` → `1999年5月6日`；同一天未填时刻的事件在具体时刻之前。只填时代的事件先于该时代内具体日期的事件。完全未知的开始时间仍排在最后，缺失更高层分组但填写了较低层时间的节点在已命名分组之后。

时间段按开始时间排入时间轴，相同起点下先显示时间段，再显示时间点。因此 `1999年—2000年5月` 的时间段在 `1888年` 时间点之后、`1999年` 时间点之前，其区间内的具体时间点也在它之后。较模糊的时间段按已填写的最精确部分与时间点比较，不推测缺失月份、日期或时刻。同一起点的多个时间段按结束时间排序；其余相同时间按创建顺序稳定排列。

数字日期统一显示为 `1234年5月6日`，旧版 `1234.5.6` 输入与中文日期排序等价。非数字日期的自定义文本保留原样。时间点只显示具体值，不重复字段名。

顶部“显示设置”提供草木、灰白、烟粉、雾蓝、黑金五套主题，时间层级可分别隐藏，完整时间仍参与排序。主题、时间层级、当前时间轴、国家、组织和角色清单折叠状态以及各时间轴筛选自动保存。版本与版权可在“认识序时”窗口底部查看。

## 保存与备份

编辑已有节点时约 650 毫秒后自动保存，也可按 Ctrl+S 或点“保存”。新增节点点击“完成”后进入时间轴；未完成的编辑以草稿保存并在重启后恢复。“取消”新增节点会删除该草稿，“结束编辑”保留已有节点已自动保存的有效修改。

桌面端每条时间轴独立保存为 JSON，通过临时文件、原子替换和上一版 `.bak` 备份保护写入。可解析的备份用于自动恢复；无法恢复时阻止覆盖损坏原文件并提示错误。请另外保存完整 JSON 备份。

仅支持 **JSON 导入导出**。导出可选当前时间轴或完整库，始终包含全部事件及格式、起止时间、手动时间顺序、其他字段、国家／组织／角色清单、筛选条件，不受当前筛选和折叠状态影响。文件对话框记住最近导出目录。

导入预览后作为新时间轴加入，不覆盖现有作品；支持格式版本 1、2、3、4。单个导入文件最多 512 MB，大型库应分批导出和导入。1.3.0 的备份格式版本 4 需使用 1.3.0 或后续兼容版本导入。

## 从源码运行

技术栈：Vue 3、TypeScript、Electron；建议 Node.js 24.x。

```powershell
npm.cmd ci
npm.cmd run dev          # 浏览器预览：127.0.0.1:5186
npm.cmd run desktop      # 构建并启动 Electron
npm.cmd test             # 业务与文件存储测试
npm.cmd run build        # TypeScript 检查及前端构建
npm.cmd run pack:release # Windows x64 NSIS 安装包
```

浏览器开发模式使用独立 IndexedDB，与桌面数据分开。真实 Electron 回归使用 `output/qa-1.3.0` 内的合成数据，按顺序运行：

```powershell
node tests/desktop-1.3.cjs create
node tests/desktop-1.3.cjs reopen
node tests/desktop-qa.cjs stress
```

重新运行一轮时通过 `XUSHI_QA_TAG` 指定新的测试目录名。`XUSHI_EXE` 可指向已安装程序以验证相同流程；测试仍使用独立数据目录。

文件存储位于 `electron/store.cjs`，JSON 文件对话框在 `electron/main.cjs`，字段迁移、排序和校验在 `src/model.ts`，时间轴和富文本编辑器在 `src/components`。时间轴通过实际测量行高的可视区域渲染支持长短事件混排。
