# 序时 · 作品时间轴

一个简单易用的故事时间轴设定工具。由 **Symplatt** 设计并主导开发，Codex 辅助实现。

**当前版本：1.6.0** · Copyright © 2026 Symplatt. 版权所有。

## 安装与更新

从 [GitHub Release](https://github.com/Symplatt/story-timeline/releases/latest) 下载 `Xushi-Setup-1.6.0.exe`，运行后从桌面“序时”快捷方式打开。安装包同时交付到本机 `D:\` 根目录。

面向 Windows 10/11 x64，采用当前用户安装，无需自行安装 Node.js。安装程序写入 Windows“已安装的应用”及卸载注册表项。请关闭旧版后安装新版；固定应用标识 `com.symplatt.xushi` 和安装目录用于覆盖更新；参照织灵使用标准 NSIS 创建“序时”桌面与开始菜单快捷方式。

作品数据独立保存在 `%APPDATA%\Xushi\workspace`。更新及卸载保留该目录；安装包和公开仓库不包含用户作品。1.6.0 兼容旧版单个国家字段、点分隔日期和 JSON 备份。旧版组织的非空层级名称转换为独立标签，原名称保留。更新前建议导出完整 JSON 备份。

## 使用

- **时间轴**：点击左上时间轴名称切换、新建、复制或删除，旁边铅笔修改名称和简介。最多保存 1000 条时间轴，每条最多 10000 个节点。复制后生成独立时间轴，默认名为“原名称的副本”，名称输入框自动聚焦并选中，可直接输入新名称。
- **添加与编辑**：右下角加号打开节点弹窗，只有事件必填。悬停或键盘聚焦节点时，旁边出现编辑、删除按钮。点击删除节点立即生效；删除整条时间轴仍需确认。
- **阅读**：中央时间轴只上下滚动。卡片按内容高度排布，默认显示前 100 个 Unicode 字符，超出显示省略号；双击卡片切换展开／收起，也可点击“显示全文”或“收起全文”。点击卡片选中，点击空白取消选择。下栏相邻显示总数／上限和筛选后数量。
- **事件格式**：支持加粗、下划线、斜体、删除线及屏蔽。屏蔽文字显示为黑色矩形，悬停或键盘聚焦揭示。屏蔽是阅读效果，JSON 仍包含原文。
- **时间**：可选择时间点或时间段，时间段分别填写开始时间和结束时间。每端都有时代、朝代、历法、日期、时刻五个文本字段，均可留空，不限制真实日历范围，允许 `1382.3.5` 和 `17:00` 等设定。时刻精确到时、分，填写时刻必须先填写日期；旧数据秒数原样保留，显示与比较按分钟，编辑保存时转为时分。留空的端点显示时间不确定。
- **地点**：1—5 共五个层级，可在显示设置中自定义名称，名称作为软件设置保存；卡片按“大地区-中地区-小地区”连接已填名称，不显示数字上标。
- **国家、组织和人物**：一个事件可关联多个国家、组织、人物，卡片中各类名称用逗号分隔。输入多个标签时用中文或英文逗号，也兼容空格、换行或 Tab 分隔，自动去重并进入已有清单。拉丁字母自然排序，中文按拼音排序，中文和拉丁文字按中文排序器分组。编辑清单可折叠，各自展开状态跨弹窗和重启保存，删除节点仍保留已录入标签以便复用。

## 筛选

左侧筛选区按字段分组，底部带下划线的“清空筛选”一键恢复全部；时间、地点、国家、组织、人物均使用独立二级侧栏，各自提供取消筛选。二级侧栏使用较轻字重与柔和文字色。各类二级栏增加 32 像素宽度，新增空间全部用于两侧留白（左侧 8、右侧 24）；打开二级栏时，卡片区域左右各增加 12 像素留白。展开时将时间轴缩至右侧剩余区域，悬浮操作按钮保持在内容上层。每条时间轴分别保存筛选条件。

- **时间范围**：开始、结束各有五层时间，均选填。边界包含在结果中；时间段事件与筛选区间部分相交也符合。只填开始时显示此后所有事件，只填结束时显示此前所有事件。较粗边界覆盖完整已知层级，例如结束为 1999 年时包含当年所有月份。启用时间筛选后，完全未知时间的事件不计入；开始晚于结束会提示并显示零结果。
- **地点**：二级侧栏同时显示五级联动表格，在一个滚动区域内按父子关系对齐。未填写的上级显示不可勾选占位符；取消父级同时取消其所有子级，选齐子级后自动选中父级。浅层事件归入父级勾选，不生成额外的空白行。每列层级名称旁的复选框可全选／全不选该级的分支，取消四级不会隐藏只填写到三级的事件。完全无地点的事件由单独开关控制。旧筛选在首次修改前保留原效果，修改后保存完整路径，重名地点不会跨上级混淆。
- **国家、组织、人物**：各自使用四列清单，滚动区域延伸到侧栏底部。标题下的放大镜搜索栏只查找选项，不改变已选项；“全选”勾选含无标签事件，取消为全不选，部分选中显示半选。国家排在组织前面，组织无层级。

不同类别与搜索条件同时生效。搜索包含事件、起止时间、地点、国家、组织和人物。结果中的搜索词高亮，匹配在正文 100 字之后时自动展开该卡片；富文本格式及屏蔽效果保留。除标签筛选搜索栏显示“搜索”外，输入框不显示 placeholder，单行输入按 Enter 后失焦；时间范围的前三层使用按已选全部上级归属过滤的下拉框，上级为“不限”时允许显示各分支名称；时间筛选修改任意层级后清空更低层级；选定朝代／历法时自动匹配已知上级，未填写的上级显示“未填写”，与“不限”区分。每条时间轴独立保存各级时间名称及其全部上级归属，空白上级也会记录。非第一层的同名时间只能在相同上级路径下复用，不能另建到不同上级；该规则包括朝代、历法、日期和时刻，数字日期按中文日期、时刻按分钟比较。即使删除最后一个引用节点或修改其名称，已经确定的归属仍然保留；编辑唯一节点、自动保存、恢复草稿和合并导入均不能改变它。旧数据从已有节点建立归属，不推断历史关系；同名冲突保留原文并提示，需将冲突节点改为不同名称，新录入及导入禁止这种冲突。节点表单的字段标题保留名称，字段组之间留出更大间距。

## 排序和显示设置

五层时间从时代向下逐层比较。时代、朝代、历法不进行数值或字母自动排序，由用户在“显示设置 → 当前时间轴的时间顺序”中分别长按条目后上下拖动编排（也可聚焦条目后按 Alt + 上下方向键），每行另有置顶／置底按钮，每条时间轴独立保存。新名称按录入先后加入列表末尾；旧数据首次打开时按节点记录中的出现顺序建立清单，之后可手动调整。日期、时刻继续按数字、字母自然排序。

共同时间部分相同时，模糊时间在前，精确时间在后。例如 `1999年` → `1999年5月` → `1999年5月6日`；同一天未填时刻的事件在具体时刻之前。只填时代的事件先于该时代内具体日期的事件。完全未知的开始时间仍排在最后，缺失上级的名称按照已知归属、或手动顺序中相邻名称的归属建立统一排序位置，再按自身手动序号排列。例如缺少时代的“明”仍可排在“清”之前；此排序定位不补写节点数据，也不推断历史归属。

时间段按开始时间排入时间轴，相同起点下先显示时间段，再显示时间点。因此 `1999年—2000年5月` 的时间段在 `1888年` 时间点之后、`1999年` 时间点之前，其区间内的具体时间点也在它之后。较模糊的时间段按已填写的最精确部分与时间点比较，不推测缺失月份、日期或时刻。同一起点的多个时间段按结束时间排序；其余相同时间按创建顺序稳定排列。

数字日期统一显示为 `1234年5月6日`，旧版 `1234.5.6` 输入与中文日期排序等价。非数字日期的自定义文本保留原样。时间点只显示具体值，不重复字段名。

顶部“显示设置”提供黑白、草木、烟粉、雾蓝、黑金五套主题，黑白排在首位且为新安装默认主题，旧主题选择保留。有值的时间层级始终显示；从最高层到该端最精确层之间的空层显示 `???`，其后的空层不显示。整条时间轴完全没用过的层级统一省略，这一判断不受筛选影响。主题、地点层级名称、编辑清单展开状态、当前时间轴、已打开的筛选侧栏以及各时间轴筛选自动保存。版本与版权可在“认识序时”窗口底部查看。

## 保存与备份

编辑已有节点时约 650 毫秒后自动保存，也可按 Ctrl+S 或点“保存”。新增节点点击“完成”后进入时间轴；未完成的编辑以草稿保存并在重启后恢复。“取消”新增节点会删除该草稿，“结束编辑”保留已有节点已自动保存的有效修改。

桌面端每条时间轴独立保存为 JSON，通过临时文件、原子替换和上一版 `.bak` 备份保护写入。可解析的备份用于自动恢复；无法恢复时阻止覆盖损坏原文件并提示错误。请另外保存完整 JSON 备份。

仅支持 **JSON 导入导出**。导出可选当前时间轴或完整库，始终包含全部事件及格式、起止时间、手动时间顺序、其他字段、国家／组织／人物清单、筛选条件，不受当前筛选和折叠状态影响。文件对话框记住最近导出目录。

导入预览在同一窗口完成。单条时间轴可选择新增或合并到当前时间轴，多条备份作为新时间轴加入。合并保留当前名称、简介、筛选及已有时间顺序，导入节点赋予新 ID 后追加，补充标签清单与未知时间名称；超过 10000 个节点时拒绝合并。支持格式版本 1、2、3、4、5、6。单个导入文件最多 512 MB，大型库应分批导出和导入。导出格式版本 6 保存完整的时间名称归属及地点完整路径筛选，应使用序时 1.6.0 或后续兼容版本导入。

## 从源码运行

技术栈：Vue 3、TypeScript、Electron；建议 Node.js 24.x。

```powershell
npm.cmd ci
npm.cmd run dev          # 浏览器预览：127.0.0.1:5186
npm.cmd run desktop      # 构建并启动 Electron
npm.cmd test             # 业务与文件存储测试
npm.cmd run build        # TypeScript 检查及前端构建
npm.cmd run pack:release # Windows x64 NSIS 安装包
```

浏览器开发模式使用独立 IndexedDB，与桌面数据分开。真实 Electron 回归使用 `output/qa-1.6.0` 内的合成数据，按顺序运行：

```powershell
node tests/desktop-1.6.cjs
node tests/desktop-qa.cjs stress
```

重新运行一轮时通过 `XUSHI_QA_TAG` 指定新的测试目录名。`XUSHI_EXE` 可指向已安装程序以验证相同流程；测试仍使用独立数据目录。

文件存储位于 `electron/store.cjs`，JSON 文件对话框在 `electron/main.cjs`，字段迁移、排序和校验在 `src/model.ts`，时间轴和富文本编辑器在 `src/components`。时间轴通过实际测量行高的可视区域渲染支持长短事件混排。
